## Concepts (read before coding)

1. **Byte-level base vocabulary.** Start from the 256 byte values of UTF-8. Every string is
   representable, so no `<unk>` token. Cost: a non-ASCII character is 2–4 base symbols until
   merges absorb it, and a single token can be a *partial* UTF-8 character.

2. **BPE training = greedy compression.** Applying a merge of pair *p* with (non-overlapping) count
   *c(p)* reduces the corpus token count by exactly *c(p)*. Picking the max-count pair is therefore
   the greedy step that maximizes compression. The objective is compression, not linguistics: tokens
   look like morphemes only because frequent byte sequences are.

3. **Pre-tokenization.** The regex splits text into chunks (words with their leading space, digit
   runs, punctuation runs, whitespace). Merges never cross chunk boundaries. Effects: tokens stay
   word-like (`" dog"` ≠ `"dog"`), and training can work on **unique chunks with counts**. Training
   cost then scales with the number of distinct chunks (tens of thousands), not with corpus size.

4. **Encoding replays merges in rank order.** Within a chunk, repeatedly apply the adjacent pair
   with the *lowest* merge id (= learned earliest). This reproduces the training-time segmentation.
   Greedy longest-match over the vocabulary does **not** (see `test_encode_applies_merges_in_rank_order`).

5. **Special tokens** (`<|endoftext|>`) get reserved ids at the top of the id space and are never
   produced by merges. `encode` maps the literal string to the special id only when allowed. In the
   data pipeline (A2) we insert EOT ids *explicitly* between stories, so story text that happens to
   contain `"<|endoftext|>"` can never inject a control token.

6. **Decoding** concatenates token bytes and decodes once at the end with `errors="replace"`.
   Decoding token by token would break multi-byte characters.

7. **Why V = 4096 here.** The embedding has V·d = 1.57 M params of ~12.3 M total. The logits tensor
   is B·T·V floats per step. A larger V shortens sequences (more bytes/token) but costs parameters
   and memory; for a narrow-domain corpus, compression saturates early.

**Determinism convention (tested):** among pairs with equal max count, choose the smallest pair
compared as `(int, int)`. Real implementations differ; we fix one so tests are exact.

## Context-length decision (D9)

Training samples random windows of `ctx` tokens from the EOT-joined token stream. If many stories
are longer than `ctx`, the model rarely sees a story's beginning while predicting its ending, which
weakens long-range coherence. Cost of 512 vs 256 for `base`: the attention FLOPs term
12·L·T·d grows from ~7 M to ~14 M per token (≈ +9% total). Activation memory per token is
roughly unchanged at equal tokens per batch.

**Rule:** if ≥ 10% of held-out stories exceed 256 tokens (EOT included), choose 512; otherwise 256.
